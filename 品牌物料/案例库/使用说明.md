## 使用方式

可以直接对 Codex 说：

> 使用 $brand-case-research，把新报告加入品牌物料案例库，和已有案例合并，保留差异与来源。

> 使用 $brand-case-research，为咖啡馆和独立书店的周末活动找资料，禁止新增印刷，给 collab-ideation 输出相关机制和反例。

> 使用 $brand-case-research，核对 C11 的销售额说法，只更新有证据支持的断言，并列出仍缺失的资料。

在项目根 `/Users/gpfs/Desktop/coding/brand` 下运行：

```bash
python3 brand-case-research/scripts/case_library.py validate 品牌物料/案例库/library.json
python3 brand-case-research/scripts/case_library.py query 品牌物料/案例库/library.json --brand 瑞幸 --limit 3
python3 brand-case-research/scripts/case_library.py packet 品牌物料/案例库/library.json --query "咖啡 数字内容 到店" --consumer collab-ideation --limit 3 --output research-context.json
```

也可用 `--case-id C11` 精确检索。关键词排序是相关性，不是合作成功率；筛选出的案例仍需结合当前目标与限制分析。

交接资料包时同时提供当前任务 brief，并说明各案例能借鉴什么、不能照搬什么。脚本本身只负责检索与证据保留，不会自动判断“不新增印刷”等业务条件。

## 给六个 Skill

六个 Skill 已补充各自的研究资料使用规则，统一通过可选 `get_context.researchContext` 获取资料。品牌整理取历史来源，创意取机制与反例，设计取产物线索，文案取表达，视觉取参考线索，质量检查取风险问题。

本地检索和资料包生成已经可运行。真实服务端 `get_context` 的自动检索/注入仍需在原运行服务开发时实现。案例中的资源、公开图片、销量和授权不会自动成为本项目的资源或承诺。

完整使用边界与接口见 [消费契约](../../brand-case-research/references/consumer-contract.md)。
