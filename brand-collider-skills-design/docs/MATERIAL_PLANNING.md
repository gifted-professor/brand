# 按品牌主营业务展开联名产物与物料

联名先回答“双方的产品、内容或服务结合后，消费者实际获得什么”，再回答“需要哪些配套物料”。咖啡以饮品为核心，首饰以可佩戴的珠宝设计为核心，3C 以设备为核心，住宿、音乐或数字业务以具体服务和内容体验为核心。主要承载方可以是 A、B 或双方，不由输入顺序决定；可以双向推出产品，也可以共同开发一个产物。

每个方向都要说明核心产物、双方贡献和具体融合方式。合作资产包括原料与风味、技术和功能、材料和工艺、审美与设计符号、IP 角色与故事、文化内容、渠道与服务；IP 是其中一种。框架没有品类白名单，首饰、鞋服、美妆、家居等可直接使用。有辨识度的外观设计本身可构成联名价值，不强制加入复杂剧情、打卡或解谜。

真正的适配由 [开放品类适配方法](../.claude/skills/brand-profile/references/CATEGORY_ADAPTATION.md) 完成：品牌资料 → 本次产品线与业务能力 → 用户动作和环境 → 可改变部位或体验及需保留功能 → 双方资产转为具体设计 → 沿使用旅程展开物料。先发散，再分类；多个主营可组成系列，陌生行业也可按属性推导。

发散可沿主营深化、邻近延伸、跨品类探索三个距离展开。探索提案需说明与品牌的关系及新增能力假设，不受现有 SKU 目录限制。复核时检查换品牌或换场景后设计是否应改变、每件是否有用途、本体是否设计清楚。六个 Skill 共用一份方法，网页会把全文纳入实际模型上下文及保存的 Skill 哈希。具体行业示例移为 [按需参考](../.claude/skills/visual-production/references/CATEGORY_EXAMPLES.md)，不会作为每个阶段的固定品牌清单加载。

对用户指定飞书视图 67 个案例的阅读与部分官方页面核对保留在 [合作产物研究与首饰补充例](COLLABORATION_PRODUCTS.md)。案例是参考，不是支持范围或模板入口。品类开放不等于每种组合已通过真实模型或生产验证。

## 候选范围

默认充分探索约 20–30 个有独立用途的候选项目，供品牌方比较。这是展开目标，不是验收门槛或数量上限；用户只要单件、预算受限、不能新增物料或不能印刷时，按实际条件收缩并说明理由。按主营产品、包装与随附、传播物料、延伸周边、场景与体验五类组织，逐件标注核心项、推荐项、可选项。

纯内容、数字和服务项目按实际触点展开，可只包含核心内容/体验及相关传播，不要求新增包装或实体周边。全案 `deliveryScope: full_collaboration` 的核心可以是 `product`（含数字产品、内容作品）或 `experience`（服务与体验）；只列泛周边、包装和宣传图不能替代全案核心。

当用户已有核心设计、明确只要特定海报/包装等时，用 `focused_deliverables`，在 `scopeNote` 说明既有依据与本轮范围，清单只列实际需要的产物。校验接受此限定范围，不要求虚构一个核心产品作为额外交付。范围是否符合用户原意由文本审查核对，结构校验不能独立判定自然语言授权。新会话仍按现有三个方向选择流程运行，本轮没有实现自动跳过该流程。

同一物品换角色、同一海报换画幅，列在该物料的变体中，不重复计数。核心项代表制作建议，不表示品牌方已经选择；候选数量也不等于本轮实际生成的图片数量。

以下为可探索的品类示例，具体项目应由双方资料、合作资产和用户约束决定；不表示已有 SKU、官方联名或已确认资源。

| 层次 | MANNER × 游戏：示例候选 | 酷态科 × 虚拟 IP：示例候选 |
| --- | --- | --- |
| 主营产品 | 角色主题咖啡、双角色饮品组合、挂耳咖啡、咖啡豆主题款 | 联名充电宝、充电器、线缆、桌面充电产品（后几项需品牌资料支持） |
| 包装与随附 | 冷饮杯、热饮杯、杯套、杯托、外带袋、饮品封签、豆袋、挂耳礼盒、故事卡 | 产品盒、内托、外封套、封签、开箱故事卡、说明书封面、收纳袋、套装礼盒 |
| 传播物料 | 发布主海报、角色系列海报、饮品菜单、社交发布图、点单页、参与说明 | 产品主海报、角色系列海报、外观细节图、使用场景图、电商主图、电商详情页、社交发布图 |
| 延伸周边 | 杯垫、随行杯、徽章、贴纸、钥匙扣、帆布袋 | 理线器、挂绳、保护套、桌垫、贴纸、钥匙扣 |
| 场景与体验 | 门店立牌、橱窗、取餐台展示、主题打卡背景 | 产品展示台、零售陈列、开箱体验、桌面场景展示 |

咖啡概念应说明“角色特征如何变成饮品配色、风味联想与杯身语言”，配方未知时标为待研发。3C 概念应说明“IP 如何进入产品表面、配色、材质和包装”，不编造功率、容量、认证，不把外观效果图解释成已验证的电子结构。效果探索先看外观和用户体验；精确尺寸、刀版与生产工艺在打样阶段细化。

| 其他主营业务 | 核心产物如何设计 | 可继续展开的候选 |
| --- | --- | --- |
| 首饰 | 把双方符号、工艺或角色特征转为吊坠轮廓、戒面、耳饰结构、宝石色彩和佩戴关系；按品牌主营形态选项链、戒指、耳饰、手链等 | 首饰盒、内托、收纳袋、擦拭布、展示托、礼赠卡、佩戴图、细节图、电商图、海报 |
| 鞋服 | 将图案、轮廓、面料、工艺或角色细节融入鞋型、服装与配饰 | 鞋盒、吊牌、防尘袋、袜子、鞋饰、穿搭图、陈列与发布物料 |
| 美妆与香氛 | 从妆效、配色或香调概念到产品和容器设计；未知配方与功效不作承诺 | 外盒、化妆包、镜子、试色卡、香卡、礼盒、试色/使用场景图 |
| 家居与生活 | 让双方材料、造型、功能在灯具、收纳、杯具、织物等实际产品中结合 | 使用配件、包装、说明、空间搭配、陈列和传播图 |
| 数字、内容与服务 | 形成具体内容作品、应用体验、住宿空间、服务流程或会员体验；说明双方贡献和用户行为 | 界面、导览、服务触点、内容封面、预告与传播素材，按需选择 |

首饰中同一吊坠换角色或材质通常是变体；项链与耳饰只有当佩戴方式、结构或用途确实不同才分别设计。款式建议不表示品牌已拥有相应金属、宝石、尺寸或生产能力。

## 已接入的网页流程

1. 品牌研究和创意阶段识别双方主营业务、可用资产与核心合作产物。
2. 统一设计阶段提交 `materialPlan`，逐件记录 ID、分类、优先级、用途、设计、合作资产表达、依赖、变体与执行条件。
3. 文案阶段读取同一份清单，按物料 ID 编写实际需要的文字。
4. 视觉阶段提交与清单一一对应的 `materialVisuals`；另有一条主图提示词，全案以核心产物为主角，限定范围取本轮优先交付项。
5. 审查阶段检查产物主次、双方资产融合、用户限制和逐件一致性。服务端拒绝缺少核心产物、重复 ID/名称、非法或循环依赖、漏项/重复/错配的单件视觉计划。
6. 画布展示每件候选及其详情，沿用“围绕这个节点继续对话”。导出的 Markdown 包含整份清单和单件提示词。

结构位于 `src/material-plan.ts`，共同策划规则与校验位于 `src/server/material-planning.ts`。CLI 与 API 使用同一份运行时校验。整套物料方法会随相关 Skill 一起加载并保存快照。

为兼容旧会话，`ipAssets`、`ipExpression` 继续作为保存字段名，其语义已扩大到合作资产与设计融合；`productAnchor.brandId` 支持 `a | b | both`。品类仍是自由文本。网页目前按两方输入协作，多方历史案例可作为研究参考，不代表已经实现任意数量参与方的独立编排。

目前支持候选清单、逐件视觉计划、画布查看与对话取舍；尚无勾选候选后自动批量生图的编排。现有“生成概念视觉”仍只请求一张产品主图。没有实际生成图片的候选保持“待选定”，不显示为完成品。

旧会话继续保留其已保存成果和创建时固定的 Skill 快照，不自动补造清单或更新整套方法。要使用完整的新适配方法，创建新会话并带入需要复用的品牌资料和方案依据。只改文案时保留设计清单并清除旧视觉计划；重新比较方向时清除失效清单，创作按新目标或环境重审适配结论。旧计划缺少 `deliveryScope` 时仍按全案校验，不改写原保存对象。
