# 画布中的角色与阶段交接

项目采用一个主控入口，按阶段安排研究、创作与审查三类专业任务。品牌 A / B 是任务关注的品牌视角，与专业角色分别记录。所有阶段读取同一会话的目标、完整标准、品牌资料、已选择方向和前序有效成果。

## 当前六个 Skill 的映射

| 专业角色 | 当前 Skill | 实际任务 |
| --- | --- | --- |
| 主控：联名总策划 | 宿主运行时 | 维护简报版本、发布交接记录、处理暂停与修改、汇总阶段成果 |
| 研究 Agent | `brand-profile` | 依次整理双方品牌资料、来源声明和信息缺口 |
| 创作 Agent | `collab-ideation` | 提出并修订三个方向，等待用户选择 |
| 创作 Agent | `design-spec` | 深化选定方向，统一双方设计 |
| 创作 Agent | `campaign-copy` | 依据统一设计形成故事与传播文案 |
| 创作 Agent | `visual-production` | 提交视觉计划及出图提示词 |
| 审查 Agent | `quality-review` | 根据完整标准进行同模型文本自检，汇总问题和未确认条件 |

这些映射沿用现有 Skill 文件及固定版本。目标中的「一个入口 + 四个专业 Skill」可以在后续经过真实项目验证后再整合；本次没有把既有六份契约改名或迁移。

## 可追踪的交接

每次实际阶段请求前，主控记录当前简报版本、专业角色、品牌视角和具体工作目标。模型请求同时带上已完成阶段、当前有效成果、完整标准、所选方向及输出要求。模型只提交自己的阶段结果，由宿主进行结构校验和保存。

`Message.role` 保持 `a` / `b` / `user` / `system` 的兼容含义。新记录额外包含 `agentRole` 和 `agentName`；成功的阶段发言包含 `skill` 与 `artifact: { section, card? }`。`artifact` 来自通过校验的真实提交，因此研究报告可以在完整方案出现前进入画布。运行中、失败、被新标准淘汰的结果不发布为成果。历史导入消息不补写未记录的专业身份或成果。

新增标准递增简报版本。仅修改文案时保留选定方向及统一设计，重做文案、视觉与审查；其他修改保留品牌研究并重新展开创意。修改到达时仍在执行的旧版结果会被丢弃。暂停允许当前请求保存有效结果，随后停止派发下一阶段。

围绕画布成果继续讨论时，`intervene` 可以接收独立的 `artifactContext: { title, content, sources }`，保存为本会话当前参考快照，并传给后续实际请求。标题最多 200 字符、内容 12000 字符、来源最多 20 项且每项 300 字符。切换成果会替换该快照；没有新快照时保留最近一次关联。只有用户本次输入的 `text` 写入标准和参与修改范围判断，参考资料内的命令不会提升为指令。快照中的状态和来源仍待核验，保留旧研究不表示研究已经按这份快照更新。

## 实现边界

当前主控是确定性的宿主编排逻辑，九个阶段调用按顺序使用所配置的文本模型。角色有不同的可信任务指令，但当前没有独立运行的 Codex 子 agent 进程，没有并行研究或额外模型的独立审查，也没有自动网页核验。画布中的角色与交接记录描述当前实际请求。

视觉阶段完成的是计划和提示词。只有用户发起生成，且当前文本方案通过出图前自检后，宿主才调用图像服务。生成中的调用记录属于创作角色；图像返回并保存前没有可展示的完成素材。生成成功也不代表已检查图像内容、获得品牌授权或通过生产验证。
