# 设计规格与修订

快速制作模式可在一次调用中共同完成深化与统一设计：只读取选定方向、双方必要研究与已核实素材，直接交付一致的设计决策和逐件物料清单。只深化选中方案，不重新比较未选候选；正文解释关键取舍，结构化清单保存产品形态、图案位置、材质、场景、参考要求和实际依赖，避免两处重复全文。独立物料允许并行，只有需要继承共用图像时才依赖母图。

网页自动制作路径在第 5–6 步形成稳定的物料 ID、优先级和真实依赖，第 6 步统一设计通过结构校验后，宿主立即按该版 MaterialPlan 启动真实参考补采，与第 7 步文案及第 8 步提示词制作并行，为后续逐件参考绑定提供依据；参考尚缺时写清具体身份要求，不能伪称映射已冻结。依赖按实际用途声明：需要复用同一杯面等上游成图的项保留等待；只承接共同设计文字或同一身份原图的独立物料不因“同系列”自动串行。提前补采只固定设计依据，不提前固定尚未生成的文案、逐件提示词或实际附图；最终绑定仍要核对这些正式输入。启用 `autoProduce: true` 的本地宿主默认制作 core 与 recommended，optional 保留候选；其他宿主按其实际记录的用户范围执行。

## 输入与输出

先按 [开放品类适配方法](../brand-profile/references/CATEGORY_ADAPTATION.md) 执行本阶段职责：承接已确定的适配依据，落实核心产品解剖、可改变部位与需保留功能，将双方资产绑定具体部位或体验，并把旅程触点转成逐件设计。沿用已确定依据，不因没有行业模板或未知生产参数阻塞概念；仅当输入或设计变化影响适配时更新相关部分。

可从 researchContext 参考产物分解、结构和履约问题；组件与资源依然以当前 brief 为准。案例中的物料、成本或授权不能直接复用为当前已确认条件。

按 [真实品牌素材与逐件附图依据](../brand-profile/references/VISUAL_EVIDENCE.md) 承接研究阶段已启动的实图采集，在方向确定时补齐选用角色/产品/Logo 的准确版本，冻结每个 materialId 的参考文件、用途、身份特征和依赖；映射存于宿主支持的附件，不新增契约字段。

输入为采用的概念、当前已知条件、品牌资源或工作假设，以及可选旧 DesignSpec 和修改说明；完整业务路径输出新的 DesignSpec。先阅读 [契约](references/CONTRACT.md)。丰富物料规划或整套制作还需阅读 [整套物料交付约定](../visual-production/references/CAMPAIGN_KIT.md)。网页简化路径的 design-b 输出 MaterialPlan；它不是完整 DesignSpec 的新字段或新契约版本，完整路径的额外物料清单仍按宿主支持的附件保存。

默认阶段是“效果探索”：沿用开放品类适配依据，将已选方向落实为具体产品或体验，再从实际使用旅程推导相关产物。未知生产参数不阻塞概念，新部件、新产品和新增服务能力仍标为提案；尺寸、刀版、结构与工艺验证在进入打样/生产范围后补。

资料稀少时继续完成文字概念与设计说明。缺预算采用有说明的试点规模，未指定型号时可提出概念产品形态；授权、渠道与生产条件集中记录为落地待确认。普通抽象图形可按设计继续，准确角色、符号、Logo 或指定产品缺身份参考时补采并标记依赖项待补素材，不能自动换成想象中的替身。概念设计可以提出新产品、包装和体验，不能声称它们已被品牌方批准或已有供应能力。

网页 MaterialPlan 新生成请求须明确 deliveryScope。整套联名用 full_collaboration，保留 product/experience 类核心项；仅当用户明确限定本轮产物且已有核心设计依据时用 focused_deliverables，在 scopeNote 说明该依据并只列本轮所需项，不添加虚假核心。该字段只扩展网页计划；旧记录缺省按 full_collaboration 解释，旧保存对象不自动补字段。

## 步骤

1. 通过实际可用上下文取得本次 baseRevision 和方向依据。用户选定、要求完成全流程后的主控代选或授权多方案继续制作均可作为相应范围的依据；记录实际决策者，不把主控代选写成用户亲自确认。只有逻辑工具实际可调用时才调用 mcp__collider__get_context。
2. 初次制作时固定适配依据、核心锚点、组件与双方贡献，写清资产作用的具体部位或体验、可改变范围和需保留功能。按使用旅程开放推导候选，再组织核心/推荐/可选层级；以实际用途和用户条件决定规模，候选计划与实际制作范围分开，角色、颜色、画幅或视角变化记为 variants。
3. 修订时先区分变化项与必须保留项。只改变用户要求涉及的部分。
4. 对每个组件填写 requiresNewItem、requiresNewPrinting 和 resourceIds；未知写 unknown。
5. 保留完整 constraintsSnapshot，逐条说明关键取舍。
6. 对核心产品或体验及相关产物写清用途、可见部位或使用状态、具体设计、展示情境、内容区、资产转译与依赖，以稳定 ID 对齐文案和提示词。核对已确定的功能边界，不以效果图编造能力；概念性改变说明依据与待验证条件。用户要求打样/生产后再补尺寸、刀版与工艺，不因缺少这些前置阻塞效果探索。
7. 固定跨物料使用的双方辨识特征、产品轮廓、配色、图形、字体与 Logo 来源，并记录主参考及衍生关系；数字服务另固定界面与体验关键状态。涉及角色时固定角色造型版本；核对官方/已批准身份源与已查看文件，为每件图写清准确保留和允许转译的部分。缺口仅影响依赖项，用户明确接受原创替代后才调整相应设计与验收范围。
8. 提交 DesignSpec，由宿主进行结构和规则检查；附件通过实际可用保存能力落盘并与当前设计引用绑定，交给 quality-review 自检。逻辑工具未实现时保留可读文件和真实哈希，不伪造服务端产物 ID。

## 修订规则

新增条件应先由宿主依据用户请求更新 brief。若当前为用户授权的 Codex 本地制作且没有该宿主更新接口，保存原 brief 引用、用户请求差量和新的本地有效条件快照后继续；不伪造服务端版本。新旧条件冲突时优先采用用户最新明确要求；仍无法同时满足时，保留原条件，给出尽量满足的替代设计及具体取舍并继续概念交付，不反复要求用户补全条件。

只改独立海报文字，不应改变 DesignSpec；改印在产品上的文字会影响视觉依赖。

禁止印刷时，不能将新印花杯套标记为现有物料来过审。复用资源必须存在且语义匹配。

## 完成条件

设计可作为逐件文案、独立物料效果图、故事和视频准备素材的共同依据。整套请求至少能从清单定位每个物料的作用、外观、输出和依赖；当前效果探索以产品和视觉设计是否成立为完成依据。生产尺寸、结构和工艺未展开不构成本阶段缺项；进入生产阶段后再按对应范围验收。锁定外观不是宣称可量产。

候选规划完成时报告适配依据、核心/推荐/可选分布及范围说明；不能把丰富候选或 MaterialPlan 保存成功称为效果图已生成。开放推导遵循 CATEGORY_ADAPTATION，字段与制作交付遵循 CAMPAIGN_KIT。
