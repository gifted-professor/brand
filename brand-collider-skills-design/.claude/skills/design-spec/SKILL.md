# 设计规格与修订

## 输入与输出

可从 researchContext 参考产物分解、结构和履约问题；组件与资源依然以当前 brief 为准。案例中的物料、成本或授权不能直接复用为当前已确认条件。

输入为选中概念、完整条件、品牌资源，以及可选旧 DesignSpec 和修改说明；输出新的 DesignSpec。先阅读 [契约](references/CONTRACT.md)。整套物料请求还需阅读 [整套物料交付约定](../visual-production/references/CAMPAIGN_KIT.md)，保存物料清单、外观设计与视觉设定附件；这些附件不增加当前 DesignSpec 的字段或契约版本。

默认阶段是“效果探索”：优先把饮品、杯托、折页、海报和已约定周边逐件设计出来，让用户看到真实可评审的外观与故事表达。尺寸、刀版、结构展开和生产工艺在用户进入打样/生产阶段时补，不作为效果图制作的前置条件，也不挤占当前核心交付。

## 步骤

1. 通过实际可用上下文取得本次 baseRevision 和方向依据。用户选定、明确委托代选或授权多方案继续制作均可作为相应范围的依据；未选概念不能自报已确认。只有逻辑工具实际可调用时才调用 mcp__collider__get_context。
2. 初次制作时固定产品身份、组件、双方贡献和视觉表现。整套请求先明确本轮交付范围与物料家族；存在画幅变体时单列，不能用一个主图的多尺寸排版补足物料家族数量。
3. 修订时先区分变化项与必须保留项。只改变用户要求涉及的部分。
4. 对每个组件填写 requiresNewItem、requiresNewPrinting 和 resourceIds；未知写 unknown。
5. 保留完整 constraintsSnapshot，逐条说明关键取舍。
6. 视觉需求写清外观材料感、颜色、图案、构图和禁止项。对饮品、杯托、杯套、故事折页等逐件说明产品形态、重要可见面、展示角度、内容区及与故事的关系；以物料 ID 对齐实际可见文案。需要展示开合效果时设计相应视图，不因此强制做完整展开稿。用户要求打样/生产后，再补精确尺寸、各面印刷、刀版、材料工艺及打样未知项。
7. 固定跨物料使用的角色造型版本、产品轮廓、配色、图形、字体与 Logo 来源，并记录主参考及衍生关系。缺少正式角色参考时可制作概念替身，但不能把不准确的角色延续成“官方一致性已通过”。
8. 提交 DesignSpec，由宿主进行结构和规则检查；附件通过实际可用保存能力落盘并与当前设计引用绑定，交给 quality-review 自检。逻辑工具未实现时保留可读文件和真实哈希，不伪造服务端产物 ID。

## 修订规则

新增条件应先由宿主依据用户请求更新 brief。若当前为用户授权的 Codex 本地制作且没有该宿主更新接口，保存原 brief 引用、用户请求差量和新的本地有效条件快照后继续；不伪造服务端版本。只有新旧条件存在实质冲突且无法从用户指令判断优先级时，才需要澄清，不能因接口尚未实现而阻断已经授权的物料展开。

只改独立海报文字，不应改变 DesignSpec；改印在产品上的文字会影响视觉依赖。

禁止印刷时，不能将新印花杯套标记为现有物料来过审。复用资源必须存在且语义匹配。

## 完成条件

设计可作为逐件文案、独立物料效果图、故事和视频准备素材的共同依据。整套请求至少能从清单定位每个物料的作用、外观、输出和依赖；当前效果探索以产品和视觉设计是否成立为完成依据。生产尺寸、结构和工艺未展开不构成本阶段缺项；进入生产阶段后再按对应范围验收。锁定外观不是宣称可量产。
