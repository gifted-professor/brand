# 方案与视觉检查

网页自动制作路径的第 8 步已逐件调用 CLI 读取原始参考和生成结果，逐件验图默认最多 2 项并行，独立于 4 个生图槽；在排队结果中优先检查有下游实际参考依赖的共用图，通过且输出哈希一致后才放行其依赖项。第 9 步汇总其实际文件、哈希、附图和审查证据，并检查整轮覆盖与缺口。总结调用可以引用这些真实检查记录，不能声称仅凭文字亲自看过图片，也不能把同模型的不同任务身份写成独立多模型评审。未启用自动制作的旧路径仍只做相应文本/出图前审查。

## 输入与输出

同一版出图前检查已通过，而本轮选中物料全部明确失败或被依赖阻塞、没有任何真实生成图片时，宿主直接展示预检依据和逐项失败原因并暂停，不重复调用整轮文字审查。此时第 9 步仍未完成，不能写成验收通过；任何实际产图都需要正常逐件检查及最终汇总。请求状态未知、未通过预检或普通文字流程不套用这项省略规则。

先按 [开放品类适配方法](../brand-profile/references/CATEGORY_ADAPTATION.md) 执行本阶段职责：复核资料、品类画像、用户动作、产品解剖、资产转译与最终产物是否对应，并检查去重、品牌替换和适配结论；不同品类按自身功能与场景验收。沿用已确定依据，不因没有行业模板或未知生产参数阻塞概念；仅当输入或设计变化影响适配时更新相关部分。

可将 researchContext 的风险事件、口径混淆和未解决差异转成当前项目的检查问题。历史案例不证明当前方案违规或失败，不能替代本次产物与真实图片证据。

按 [真实品牌素材与逐件附图依据](../brand-profile/references/VISUAL_EVIDENCE.md) 检查真实网页来源、已下载/已查看文件、每件物料冻结的映射及实际调用附图证据；出图前校验身份依据，出图后对照原图验收。风格参考、生成图和“看起来像”均不能证明官方身份。

输入为当前 brief、设计、文案、渲染计划，以及实际输出；输出 ReviewReport。先阅读 [契约](references/CONTRACT.md)。整套物料验收还需阅读 [整套物料交付约定](../visual-production/references/CAMPAIGN_KIT.md)，检查清单与逐件证据；附件验收不新增 ReviewReport.stage 或 verdict。

审查当前交付层级是否成立。用户只提供名称或简述时，同样检查概念的双方贡献、消费者价值、完整度与一致性；未提供预算、商业批准或生产参数本身不构成阻断。准确品牌/IP 图像缺必需身份来源、实际附图或视觉查看证据时，相应项不能通过；检查假设是否被误写成事实，保留具体缺口并继续独立项与文字。

## 创意赛马与方案成熟度

检查内部候选与逐项评审记录是否真实存在；默认十二个候选、最终最多三个。不能把生成三项后补写的排名称为十二进三。

同一 Skill 分阶段执行时检查提出阶段的实际候选记录和收敛阶段的修改依据，不要求两个阶段各自重做完整赛马，也不要求最终方案在 section 与 concepts 重复保存。

对候选先看双品牌必要性、消费者所得、明确产物、目标作用路径和关键执行依赖。需要淘汰时写出具体缺陷；旧推荐没有保留名额，不用热闹程度或综合分掩盖贴标、矛盾与弱价值。

对入围方案检查产品组成、完整参与过程、双方收益、最小执行、经济逻辑、视觉场景、验证方式和未知项是否齐全。若只有一至两个合格就保留实际数量。原候选均不成立时指出具体失败点和可行替代，检查修订后的最小方案；不把“补资料”当作唯一建议，也不伪称原候选通过。评审附件不是新的 ReviewReport.stage，也不等于出图前通过。

## 出图前

1. 从实际可用上下文读取当前有效条件与精确产物引用；mcp__collider__get_context 可用时才调用，不编造逻辑工具结果。
2. 按开放品类适配方法复核画像与证据、使用环境、用户动作、核心产品解剖、资产转译及最终产物是否对应；检查品牌替换后是否仍几乎无需修改。允许新产品探索与非实物核心，检查提案标记和保留功能，不因缺少行业模板或复杂活动机制判为不合格。
3. 比较条件、组件字段、描述和视觉提示，寻找“声明不印刷但画面要求印花”等矛盾。
4. 检查已有资源引用及其语义，不接受凭空制造的现有物料；逐件核对官方/已批准身份源、已查看文件哈希、选定版本与参考映射，确认实际模型能接收必要附图。缺失项不能用近似图形或文字 URL 绕过。
5. 检查文案是否增加未设计的赠品、价格、日期或官方合作声明。
6. 提交 pre_render 报告，严重问题给出具体修复点。

## 整套交付覆盖

先按用户实际范围检查 MaterialPlan.deliveryScope：full_collaboration（旧记录缺省值）要求至少一项 core 属于 product 或 experience；focused_deliverables 仅用于用户明确限制本轮交付且核心已有设计依据的任务，scopeNote 应说明范围与复用依据，不因清单未新增核心项而拒绝，也不接受虚假核心项。再检查候选是否由使用旅程和具体作用推导、适配依据与已知能力是否区分、核心锚点是否明确；固定分类不要求每类齐全，数量不替代质量。相同物品的角色、配色、尺寸或视角变化记为 variants；检查独立用途、重复 ID 和循环依赖。

网页 design-b 的 MaterialPlan 和 visual-b 的 MaterialVisual[] 只证明计划及提示词存在；逐件提示词应与当前清单 ID 一一对应。启用 autoProduce 的宿主另提供逐件自动制作状态、真实输出与检查证据，验收须读取这些记录；计划本身不是完整 DesignSpec/RenderPlan payload，也不是实际生图结果。默认核对 core 与 recommended 的本轮制作覆盖，optional 保留为范围外候选。

再逐项对照当前授权制作清单：默认效果探索阶段，实体产品及相关包装、传播、周边应有真实可评审的逐件效果图；数字、内容、服务应有对应界面、内容或流程效果，不强加实物图，总览板不能替代逐件输出。候选数、实际制作物料数、文件数和变体数分别统计；未纳入制作的可选项不判为生成失败。尺寸、刀版、结构展开及生产规格仅在用户进入相应阶段后纳入必验项。本阶段验证主题和设计表达，剧情型方案才要求完整动机、事件、因果、转折和收束；视频提示词或分镜占位不能算已生成关键帧或视频。

检查双方辨识特征、产品、图形、文案及体验关键状态在产物及镜头间是否一致，实际使用的参考来源是否可追溯；涉及角色时再检查角色身份。当前先验收外观、产品、内容和体验表达是否成立；概念效果与生产或上线验证保持分开。若另含结构示意或生产文件，按它们实际层级标记，不让附加结构内容挤占效果图交付或把生产未知项升级为本阶段阻断。已确认的身份问题不能因画面好看而略过。

统一入口应可打开所有约定输出，并有真实文件路径或服务端素材 ID、哈希、版本和依赖。逐件列出已制作、已检查及未解决问题；部分文件通过不能覆盖其他物料缺失，未生成项不能计入产量。整包结论必须限定实际层级与范围，例如“准备文件齐全，关键帧尚缺”，不得用一个 all-pass 隐藏缺口。

## 出图后

1. 通过实际可用的 mcp__collider__read_asset 或当前宿主的文件/图像读取能力逐件查看真实输出；不编造逻辑工具调用。视频在范围内时检查实际片段与成片，不能仅凭脚本检查视频。
2. 检查组件、配色、产品身份、禁止元素、文字可读性和概念标记；对照实际参考检查角色服饰/配件、符号轮廓、Logo 字形及指定产品结构，核对每个 materialId 的真实调用附图与冻结映射一致。披露“非官方”不能弥补身份错误。
3. 每项问题引用实际产物或素材，不把提示词当作图片证据。
4. 无视觉能力、读取失败或关键细节看不清时，visualInspection 为 unavailable 或说明局限，结论不能是完整 pass。
5. 提交 post_render 报告，供宿主决定继续修订、待人工审核或完成。

## 判断纪律

同 Agent 自检不是独立评估；模型结论不能覆盖确定性规则。图已生成不代表满足条件，更不代表品牌授权或生产可行。

只报告能观察或能从有效数据验证的事项。资料、预算、官方授权和生产参数缺失时，以 warn/info 与 limitations 保留落地待确认，并评审现有概念，不因此把整案判为 needs_input。未实际读取的视觉结果仍为 unverified；虚构事实、明显矛盾或未完成产物要如实指出，给出可执行的替代或修复，不以通过结论掩盖缺口。

有界修复由当前宿主限额、用户授权范围及具体失败原因决定，不固定为历史上的一轮。用户的新修订指令可以启动相应范围的新修复；不能凭 Skill 自行增加付费限额。每次修复说明目标、证据、可验证变化和停止条件，只复查受影响项。来源不足时先补采；准确身份依赖仍缺则暂停相应图像项，继续文字与独立项，只有用户明确接受原创替代才改变其验收范围。请求状态或计费未知时先核查，不自动重发；限额用尽或连续同类工具失败且无有效改法时停止相应生成项并返回准确状态，继续整理已有成果、替代方案与最终交付，不把技术失败写成用户资料不足。
