# 联名整套物料交付约定

用于任意品类品牌联名的丰富产物规划，以及方向确定后产出核心产品或体验、相关包装、传播、周边和所需 AIGC/视频素材的场景。双方可以都是实体品牌，也可以贡献内容、技术或服务，不要求有虚拟 IP。规划可以先于真实制作；单件改图、改文案仍按原有窄范围执行。完整业务产物契约、网页工作台结构化计划和真实生成文件是三个不同层级，不混作已实现能力。

工作流版本：1.6.1。品牌/IP 视觉依据统一执行 [真实品牌素材与逐件附图依据](../../brand-profile/references/VISUAL_EVIDENCE.md)：研究开始即与文字分析并行采集真实网页图片，创意提出前汇合初始采集与实际核对结果或缺口，选向后补齐实际版本并冻结逐件映射，制作时实际附图，验收时对照原文件。

## 先确定双方共同创造的核心产物

核心选择依据由共享适配方法维护：先识别本次产品线、消费者动作与环境，以及产品部位或体验环节，再明确双方贡献。多个主营产品或服务可以共同构成核心系列；根据实际使用旅程展开相关包装、传播、配件、内容或体验。外观、风味、工艺、功能或收藏表达本身可构成联名价值。

品牌名不等于能力事实。用户指定的核心品类可作为任务依据；具体 SKU、材质成分、工艺、配方、外壳结构、接口、功率、容量、授权、服务覆盖和现有配件需有实际依据。效果探索中可提出新设计，但明确其为概念提议，不能写成已确认性能、已开放服务或可生产承诺。

## 丰富候选与制作范围分开

用户希望有更多选择且品类和范围适合充分展开时，可用 **20–30 个有独立作用的候选** 作为探索软目标，按核心、推荐、可选分层；它不是所有项目的默认实物订单或最低数量。以实际品牌能力、用户输入、预算和有效限制决定规模；窄范围、首饰单品或数字服务合作都可只保留少量有价值的项目。不要为凑数新增无关实物、换角色、改颜色、换尺寸或拆分视角。十二进三限制创意方案数量，不限制每个方向的候选数量。

- 核心：明确承载双方合作价值的产品或体验及完成其表达所需的输出。实体产品保留主营产品设计和必要包装；数字、内容、服务合作保留核心界面、内容或服务体验，不要求出现实体 SKU。
- 推荐：对购买、携带、使用、展示、参与或传播有清楚作用，能完善本次联名的一组产物。
- 可选：让品牌方继续挑选的延伸配件、收藏周边或体验设计；写清用途与依赖，不把它们默认加进实际制作。

优先级是建议，不表示正式选定、已生成或可量产。候选计划可以充分展开，实际制作遵循本轮用户范围、宿主能力与预算；只有已经授权的范围才连续执行，不为每件重复确认。仅有计划和逐件提示词不构成生图授权；本项目实时网页明确记录 autoProduce: true 时，由宿主默认将 core 与 recommended 纳入本轮制作，optional 保留候选，并在第 8 步连续生成与逐件验收。历史记录未带该字段或为 false 时不自动启动批量。其他宿主沿用其实际记录的任务范围。

## 从适配依据生成这一包

先沿用 [开放品类适配方法](../../brand-profile/references/CATEGORY_ADAPTATION.md) 得到的业务、用户场景、产品部位/体验和双方融合结论，再决定交付项目。分类仅用于整理候选，不从固定行业物料表开始填空。方法允许主营深化、邻近延伸和有品牌连接的探索提案；按用户意图展开，不把现有 SKU 目录当作创意边界。

需要对照具体写法时按需读取 [品类示例](CATEGORY_EXAMPLES.md)。示例不会作为每个网页步骤的固定输入；没有对应行业示例也可按共享方法推进。

## 先确定这一包的范围

记录方向、选择/代选依据、当前设计与文案引用、丰富候选与本轮需要实际生成的物料之间的关系、预算或宿主限额，以及最终交付层级。用户要求整套完成即支持范围内连续制作，无需逐件重新确认；“为后续视频准备”不自动授权生成成片。未选概念可做明确标记的深化示范，不能冒充已确认方案。

不同方案分别建包并保持独立身份。共享品牌来源可复用，不能混用两个方案的产品和故事。所谓一次完成是覆盖已约定的交付清单，不代表一次模型调用，也不代表所有未知生产条件已获解决。

将用户点名的每类需求逐一映射到清单。对“周边”说明本案选用的具体实体或数字产物及用途；对“视频准备包”说明各镜头已有、将制作或暂缺的参考素材与关键帧，不能无声缩成纯文本。常规视觉细节由执行者自主细化并简短告知，不变成逐项审批。

默认阶段是“效果探索”：重点交付本轮范围内的核心产品或体验、相关包装、传播及周边逐件效果图，以及支撑它们的产品设计、主题表达和已约定筹备素材。仅要求计划或提示词时如实交付对应层级。用户锁定创意方向不自动等于要求生产落地。精确尺寸、刀版、结构展开、工艺与完整印刷面规格在用户进入打样/生产阶段时再补，不要求先完成这些才出效果图，也不让它们挤占本阶段核心交付。已有结构稿可以作为附录，但不能代替独立物料效果图。

## 网页 MaterialPlan 与完整产物契约

网页简化流程的 `design-b` 使用结构化 `MaterialPlan`；`visual-b` 提供与当前清单 ID 一一对应的 `MaterialVisual[]` 和主视觉 `imagePrompt`。它们属于工作台数据，不能当作完整 `DesignSpec`、`RenderPlan` 或新的 `ArtifactRecord` payload。完整产物继续遵循各自的 1.0 契约；旧 `DesignSpec.components[].kind` 未覆盖的具体产品仍按受支持字段及明确描述表达，不能静默扩充枚举。

`MaterialPlan` 字段与 `src/material-plan.ts` 对齐：

- `deliveryScope`：`full_collaboration | focused_deliverables`。全案使用前者；仅当用户明确限制交付且已有核心设计依据时使用后者，并在 scopeNote 说明依据。新生成请求明确范围，旧记录可省略并按全案校验，不自动改写旧对象。
- `productAnchor`：`{ brandId: "a" | "b" | "both", category, coreProduct, rationale, ipAssets: string[], translation }`，分别说明核心由哪方承载（`both` 为双方共同提供）、自由文本品类、核心产品或体验、选择理由、合作资产与具体融合方式。
- `scopeNote`：本轮范围、假设与数量取舍；明确候选和实际制作的区别。
- `items[]`：`{ id, name, category, priority, role, design, ipExpression, dependencies, variants, feasibility }`。
- `category`：`product | packaging | communication | merchandise | experience`；`priority`：`core | recommended | optional`。全案 `items` 至少含一项 `priority: core` 且 `category` 为 `product` 或 `experience` 的核心产物；产品包括数字产品或内容，体验包括服务，不强迫实物。限定范围只列用户指定产物，可以全部为传播、包装或周边；productAnchor 是既有设计依据，不为过校验而新增核心项。
- `ipAssets` 与 `ipExpression` 保留旧字段名以兼容存储，语义分别为“合作资产”和“合作资产融合表达”，不要求 IP 或角色。`role` 说明用途与消费者价值，`design` 写具体外观、内容、功能或体验表达；`dependencies` 是本清单中上游物料 ID 数组，`variants` 是角色/颜色/尺寸等变体说明数组，`feasibility` 写执行条件与未知项。`id` 必须稳定且唯一，不用名称代替依赖引用，不建立循环依赖。
- `MaterialVisual`：`{ materialId, prompt }`。每项必须对应当前 `items[].id`，逐件提示词写该产物的产品外观或体验状态、合作资产融合、展示角度、文字内容区与禁止项；同一总览提示词不能复制给所有项目。

全案的主视觉以核心产物为主角；限定范围的主视觉取本轮优先交付项，不另外增加用户未要求的产品图。

`MaterialPlan` 不含已生成状态，`MaterialVisual` 只是待执行提示词。真实文件、生成调用、检查结论另按实际宿主记录，不把候选优先级或提示词存在当作制作证据。

## 物料清单：家族、视面与变体分开

根据核心产品或体验和实际接触点选择独立产物，按实际范围提供丰富候选，不强制固定数量或每类齐全。产品、包装、传播、周边、体验是分类；具体咖啡杯、充电宝、首饰、收纳包、服务引导页或主海报才是物料家族。视频准备素材属于输出层级，不能混入实体周边数量。

每个清单项使用稳定的本地 `materialId`，记录：

- 家族、核心/推荐/可选优先级、使用场景、消费者看到或做什么；剧情型方案另记录对应故事节点。
- 产品与可见表达：例如饮品形态、充电宝外壳、首饰佩戴、包装开箱、内容界面或服务接触点；记录合作资产融合、关键视角或使用状态、材料感、图形、文案 ID 及与主题的关系，不强制穷举不可见底面或所有印刷面。
- 当前阶段：效果探索或用户要求的打样/生产。进入后者才补尺寸、刀版、裁切/折线和工艺依据；效果探索不要求供应商规格。
- 输出层级：效果图、可编辑平面稿、结构概念展开稿、供应商生产稿，或脚本、分镜表、实际参考帧、实际视频。
- 本家族需要的角色/配色/画幅等变体、目标路径、上游设计/主题/参考资产依赖和验收标准。

同一海报的方图、竖图和横图是一个家族的三个尺寸变体；同款充电宝换角色配色、同套徽章换角色、同款饮品形成角色风味系列，均在对应项内记录 variants，不拆成多件充数。不同视角、正反面、效果图与展开设计也是该物料的视面或输出层级。展开设计只有被纳入打样/生产范围后才成为必要项，不能默认判为缺失。分别报告候选项数、本轮实际制作物料数、文件数与变体数。

## 故事与美术共同依据

主题附件说明一句话设定、双方为何共同形成该核心产品或体验、具体设计与消费者所得。外观、风味、工艺、功能或收藏型联名可用简明设计说明，不强制虚构角色动机、互动系统或多幕剧情。方案本身包含剧情、角色扮演或解谜时，再补开端—事件—选择/转折—结局、真实线索/规则与结果。传播按实际触点安排信息递进，写清各物料的新增信息和行动。

美术设定固定双方辨识特征、主营产品轮廓、比例与组件数量、界面或体验关键状态、主辅色、图形语言、字体、Logo 处理和环境光；涉及角色时另固定角色版本。3C 产品保留已确定的结构与接口位置，首饰保留明确的造型与佩戴结构，不凭画面新增功能或证明工艺。按共享视觉依据登记来源页、图像地址、发布者/日期、实际文件/哈希/尺寸、来源类别、版本、查看记录和用途；按 materialId 冻结采用的参考与必须保留的身份特征。官方页面或图片地址不是已登记的服务端 assetId；风格参考和生成角色不能充当准确身份来源。

逐件文案按清单 ID 对齐，效果探索先落实各物料实际展示的内容区及叙事有用的内外面，不等待精确尺寸与完整印刷面表。事实说明、活动价格和日期必须有依据；未知事项留在制作说明中。成品表达以消费者能理解和行动为准，不把内部流程、生成参数或验收术语写进宣传正文。概念披露放在适当位置。

## 制作顺序与复用

真实素材采集从研究开始并行执行，设计选定后补齐采用的准确版本及每件参考映射；不等设计完成才开始找图。本地宿主在统一设计提交后提前启动该版计划的补采，与文案和逐件提示词制作并行；正式提示词与补采完成后才冻结最终映射。固定核心产品或体验设计、主题、本轮范围及已查看参考后，优先生成并验收有共享依赖的关键画面，再展开独立物料和必要变体。核心产物与必要承载优先；不能先堆通用周边却缺少核心设计。每件使用明确的计划与上游引用；依赖变更只使受影响项待更新，不默认重生全部素材。

真实生图默认采用**最多 4 个在途任务的滑动窗口**，上限取 4、供应商实际限额和宿主实际限额中的最小值；不足 4 项就绪时按实际数量执行，不为凑并发越过依赖或身份检查。单次调用可附几张参考图另按模型能力检查，不能把“4 张参考图”当成“4 并发”。具体调度如下：

1. 每项必须有当前设计、已冻结且可实际附入的参考、通过的出图前检查，以及已就绪的上游依赖。准确身份素材仍缺的项等待补采，普通独立概念和文字继续。
2. 共用产品主图/角色设定等关键图先完成并通过身份检查；依赖它们的物料再进入队列。无该依赖的项可同时运行。验图独立限流，本地默认最多 2 项，不占用 4 个生图槽；优先检查被尚未生成任务实际引用的共用图，核对实际输出哈希后放行依赖。
3. 每当一项明确完成或失败，立刻保存实际调用附图列表、请求/文件证据和逐件状态，并补入下一个就绪项，不等待一组 4 项全部完成。画布有实际更新能力时逐件回传；没有时保存真实状态附件，不声称 UI 已更新。
4. 单项失败只暂停该项及依赖它的项，继续其他就绪任务；有界重试同样占用并发名额。超时且供应商状态/计费未知时先核查，不重复付费，该请求未确认终止前仍计入在途名额，不能靠重发突破并发上限。

此约定不创造新的批量 MCP。本项目 autoProduce 宿主已有四槽执行、逐件 CLI 看图、状态持久化与网页展示，按 [本地执行方法](LOCAL_EXECUTION.md) 调用；独立脚本与其他宿主不自动继承网页能力。真实能力仅支持串行时如实采用串行并记录能力缺口；已有四槽能力时，就绪一项即可启动，不能因等待凑满四项或整批结果而退化为串行。

本轮纳入制作的实体产品、包装、传播与周边各自形成可评审的独立效果图，展示消费者实际会看到的外观和使用情境；数字、内容或服务则交付对应界面、内容或流程效果，不能以实物包装图替代。必要时增加特写、开合视角或体验状态来讲清设计，不因此强制提交平面稿、结构展开或完整尺寸表。用户要求打样/生产后，再按实际范围补可编辑平面稿、尺寸和供应商刀版并验收；效果图本身不证明生产性能或服务已上线。

海报既可以复用产品主图做说明，也可以针对故事节点设计独立发布画面。旧 poster_compose 仅支持前者。使用真实可用工具生产其他输出，不能改写旧接口含义或假称已有批量编排功能。

## 为 AIGC 与视频准备

准备包按当前范围包含脚本、镜头表、提示词和实际素材。镜头表记录镜头 ID、时长/时间段、剧情作用、画面动作、景别/镜头运动、角色与道具状态、台词/旁白、画面文字、声音/转场、参考素材 ID、连续性要求与生成状态。

实际参考帧或关键帧必须对应真实生成/选用且已查看的图像，注明覆盖的镜头；绘有框线的分镜占位、文字提示词或“待生成”路径不是关键帧。首尾帧、角色多视图、纯场景、产品独立图或分层文件仅在镜头和后续模型确实需要时制作，不用无关资产堆数。模型对时长、参考数量、首尾帧和声音的支持以当次真实能力为准。

在用户仅要求筹备时，成片记为本轮范围外，不计为失败或已完成；若已约定实际关键帧则应生成并验收，不能只给提示词结束。用户要求成片时继续实际生成、编辑和检查，最终另给实际视频路径及元信息；准备文件齐全不等于成片完成。

## 状态、真实索引与验收

提供一个可打开的入口，链接全部物料、文案、故事、镜头表和检查记录。索引至少记录本地 materialId / assetId、真实文件路径或宿主 ID、SHA-256、输出层级、家族/视面/变体、来源及依赖、生成调用记录（若有）和检查状态。每个实际生成项还应能定位参考映射版本、真正提交的附图文件/哈希、身份/风格/一致性用途与输出对应关系；不能只链接素材库或 prompt 代替调用附图证据。本地 ID 只是包内标识，不能伪装成服务端 ArtifactRecord；服务端 ID、版本和哈希仅用真实返回值。

区分执行状态（计划、已生成/已保存、失败、待输入/待补素材、范围外）和验收结论（未检查、通过、需修订及局限），使用宿主既有状态字段或可读附件描述，不擅增枚举。导出文件存在不等于品牌表达正确、排版合格、可生产或服务已上线。效果探索逐件实际打开检查文字、产品外观或体验表达、双方辨识度、跨物料一致性、故事表达和约定展示视角；准确角色/符号/Logo 对照真实身份来源检查，不能只检查颜色与画风。尺寸、结构和工艺等生产验收仅在进入相应阶段后执行。视频检查实际片段/成片，不能以提示词替代证据。

整体结论根据约定范围汇总并保留局限，例如“24 项物料候选和逐件提示词齐全，实际图片尚未生成”或“本轮 6 件效果图中 1 件待修”。不要在缺少必要物料、正式参考或检查证据时宣称整套 all-pass。修复遵循当前用户/宿主范围及明确停止条件，计费状态未知时不重复提交付费请求。网页有结构化候选展示不等于完成逐件生成、状态管理和真实文件导出，保存附件本身不是上线证明。
