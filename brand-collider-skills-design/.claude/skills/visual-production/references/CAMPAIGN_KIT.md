# 联名整套物料交付约定

用于用户要求方案敲定后一次产出包装、传播故事、海报、周边以及后续 AIGC/视频素材的场景。它扩展现有 design-spec、campaign-copy、visual-production 和 quality-review 的附件职责，不增加业务 payload 类型、逻辑 MCP 或已实现能力。单件改图、改文案仍按原有窄范围执行。

## 先确定这一包的范围

记录方向、选择/代选依据、当前设计与文案引用、本轮需要实际生成的媒介、预算或宿主限额，以及最终交付层级。用户要求整套完成即支持范围内连续制作，无需逐件重新确认；“为后续视频准备”不自动授权生成成片。未选概念可做明确标记的深化示范，不能冒充已确认方案。

不同方案分别建包并保持独立身份。共享品牌来源可复用，不能混用两个方案的产品和故事。所谓一次完成是覆盖已约定的交付清单，不代表一次模型调用，也不代表所有未知生产条件已获解决。

将用户点名的每类需求逐一映射到清单。对“周边”说明本案选用的具体实体及用途；对“视频准备包”说明各镜头已有、将制作或暂缺的参考素材与关键帧，不能无声缩成纯文本。常规视觉细节由执行者自主细化并简短告知，不变成逐项审批。

默认阶段是“效果探索”：重点交付杯托、饮品、折页、海报等逐件实物/传播效果图，以及支撑它们的产品设计、完整故事和视频筹备素材。用户锁定创意方向不自动等于要求生产落地。精确尺寸、刀版、结构展开、工艺与完整印刷面规格在用户进入打样/生产阶段时再补，不要求先完成这些才出效果图，也不让它们挤占本阶段核心交付。已有结构稿可以作为附录，但不能代替独立物料效果图。

## 物料清单：家族、视面与变体分开

根据方案实际接触点选家族，不强制每次做固定数量。常见家族包括杯/杯套、杯托、提袋、故事卡/折页、门店海报、菜单/参与说明、社交传播图以及视频准备素材；只做有产品或叙事作用的项。

每个清单项使用稳定的本地 `materialId`，记录：

- 家族、使用场景、消费者看到或做什么、对应故事节点。
- 产品与可见外观：例如饮品形态、杯托装杯状态、折页打开后的故事内容；记录关键视角、材料感、图形、文案 ID 及与故事的关系，不强制穷举不可见底面或所有印刷面。
- 当前阶段：效果探索或用户要求的打样/生产。进入后者才补尺寸、刀版、裁切/折线和工艺依据；效果探索不要求供应商规格。
- 输出层级：效果图、可编辑平面稿、结构概念展开稿、供应商生产稿，或脚本、分镜表、实际参考帧、实际视频。
- 本家族需要的画幅/尺寸变体、目标路径、上游设计/故事/参考资产依赖和验收标准。

同一海报的方图、竖图和横图是一个家族的三个尺寸变体。杯托效果图与展开设计属于不同层级的输出：当前效果探索以独立杯托效果图为核心；展开设计只有被纳入打样/生产范围后才成为必要项，不能默认判为缺失。数量分别报告“家族数、文件数、尺寸变体数”，不互相替代。

## 故事与美术共同依据

故事附件至少包含一句话设定、角色动机、开端—事件—选择/转折—结局，以及消费者和实际产品如何参与。按预热、发布、参与、分享/回访安排信息递进，写清每个触点的新增信息和行动。为角色扮演或解谜活动提供完整事件、线索/规则与结果，而不是只提供一个故事标题。

美术设定固定角色版本与辨识特征、产品比例和杯数、主辅色、图形语言、字体、Logo 处理和环境光。登记每个来源的路径/URL、来源类别、使用范围、核验状态及实际采用的参考文件。官方页面或图片地址不是已登记的服务端 assetId；未经核验的生成角色不能冒充正式模型设定。

逐件文案按清单 ID 对齐，效果探索先落实各物料实际展示的内容区及叙事有用的内外面，不等待精确尺寸与完整印刷面表。事实说明、活动价格和日期必须有依据；未知事项留在制作说明中。成品表达以消费者能理解和行动为准，不把内部流程、生成参数或验收术语写进宣传正文。概念披露放在适当位置。

## 制作顺序与复用

先固定故事和设计，再准备共享角色/产品/场景参考，随后生成关键画面、独立物料和必要尺寸变体。每件使用明确的计划与上游引用；依赖变更只使受影响项待更新，不默认重生全部素材。

当前先让杯托、杯套、饮品、折页与海报各自形成可评审的独立效果图，展示消费者实际会看到的外观和使用情境。必要时增加特写或开合视角来讲清设计，不因此强制提交平面稿、结构展开或完整尺寸表。用户要求打样/生产后，再按实际范围补可编辑平面稿、尺寸和供应商刀版并验收；效果图本身不证明生产性能。

海报既可以复用产品主图做说明，也可以针对故事节点设计独立发布画面。旧 poster_compose 仅支持前者。使用真实可用工具生产其他输出，不能改写旧接口含义或假称已有批量编排功能。

## 为 AIGC 与视频准备

准备包按当前范围包含脚本、镜头表、提示词和实际素材。镜头表记录镜头 ID、时长/时间段、剧情作用、画面动作、景别/镜头运动、角色与道具状态、台词/旁白、画面文字、声音/转场、参考素材 ID、连续性要求与生成状态。

实际参考帧或关键帧必须对应真实生成/选用且已查看的图像，注明覆盖的镜头；绘有框线的分镜占位、文字提示词或“待生成”路径不是关键帧。首尾帧、角色多视图、纯场景、产品独立图或分层文件仅在镜头和后续模型确实需要时制作，不用无关资产堆数。模型对时长、参考数量、首尾帧和声音的支持以当次真实能力为准。

在用户仅要求筹备时，成片记为本轮范围外，不计为失败或已完成；若已约定实际关键帧则应生成并验收，不能只给提示词结束。用户要求成片时继续实际生成、编辑和检查，最终另给实际视频路径及元信息；准备文件齐全不等于成片完成。

## 状态、真实索引与验收

提供一个可打开的入口，链接全部物料、文案、故事、镜头表和检查记录。索引至少记录本地 materialId / assetId、真实文件路径或宿主 ID、SHA-256、输出层级、家族/视面/变体、来源及依赖、生成调用记录（若有）和检查状态。本地 ID 只是包内标识，不能伪装成服务端 ArtifactRecord；服务端 ID、版本和哈希仅用真实返回值。

区分执行状态（计划、已生成/已保存、失败、待输入、范围外）和验收结论（未检查、通过、需修订及局限）。导出文件存在不等于角色正确、排版合格或可生产。效果探索逐件实际打开检查文字、产品外观、角色身份、跨物料一致性、故事表达和约定展示视角；尺寸、结构和工艺等生产验收仅在进入相应阶段后执行。视频检查实际片段/成片，不能以提示词替代证据。

整体结论根据约定范围汇总并保留局限，例如“文本筹备齐全；两张关键帧待修；包装为概念稿”。不要在缺少必要物料、正式参考或检查证据时宣称整套 all-pass。修复遵循当前用户/宿主范围及明确停止条件，计费状态未知时不重复提交付费请求。网页对这些附件的逐件编排、状态管理及导出仍需实现，保存附件本身不是上线证明。
