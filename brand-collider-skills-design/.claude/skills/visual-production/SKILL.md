# 联名物料与视觉制作

在有本地文件和视觉能力的宿主执行真实采集、最多四并发生图及共用图检查时，读取 [本地执行方法](references/LOCAL_EXECUTION.md)。本项目网页启用 `autoProduce: true` 后，第 6 步统一设计后宿主已启动参考补采，第 8 步的专业 CLI 与其并行提交逐件提示词；宿主汇合两条支线后完成最终绑定、出图前检查、四槽制作和逐件 CLI 看图验收。Agent 不自行开启 shell 或重复启动批次；其他宿主仍按实际能力执行。

## 输入与输出

先按 [开放品类适配方法](../brand-profile/references/CATEGORY_ADAPTATION.md) 执行本阶段职责：把当前产品解剖、功能边界与资产转译落实为可见部位、使用状态和展示情境；依已确定的旅程与清单制作，不从固定物料分类重新发散。沿用已确定依据，不因没有行业模板或未知生产参数阻塞概念；仅当输入或设计变化影响适配时更新相关部分。

可从 researchContext 参考构图、表现手法和素材线索。网页 URL 与案例 ID 不是可用素材 ID；未经当前素材登记与使用权确认，不把历史图片或标识当作参考资产提交。

必须按 [真实品牌素材与逐件附图依据](../brand-profile/references/VISUAL_EVIDENCE.md) 使用研究阶段已采集、设计阶段已冻结的逐件参考映射；生成前核对真实文件、视觉查看记录和实际附图能力，生成后保留每个 materialId 的实际附图证据并对照身份。风格图与 AI 一致性图不能代替官方身份来源。

缺少商业批准或生产参数不阻断已授权概念制作；普通抽象图形、原创场景和新产品提案仍可生成。准确角色、符号、Logo 或指定产品缺身份依据时先补采，仍缺则只暂停依赖项，不自动改成近似替身。用户对概念制作的授权与品牌方商业批准分别记录，不把后者当作前者的先决条件。

输入为当前设计、文案、物料计划、风格包、模板和已有素材。先阅读 [契约](references/CONTRACT.md)。丰富物料规划或整套请求必须阅读 [整套物料交付约定](references/CAMPAIGN_KIT.md)。以核心产品或体验及双方资产的具体融合为先，从核心/推荐/可选候选中按本轮范围制作，不能在交付两张总览卡片或几个尺寸变体后宣称整套完成。实体产品、相关包装、传播和本轮周边应有独立效果图；数字、内容和服务提供对应界面、内容或体验效果，不强加包装和实体赠品。尺寸、刀版与结构展开在用户要求打样/生产后再补。

完整 RenderPlan、image_generate 与 poster_compose 契约仍只覆盖既有主图和复用主图海报路径，不擅自添加 payload 字段或虚构批量物料/视频 MCP。网页简化路径的 visual-b 根据 MaterialPlan 输出与 items[].id 一一对应的 MaterialVisual[]（materialId、prompt）和总览 imagePrompt；逐件提示词不是实际图片；本项目网页只有已记录 `autoProduce: true` 才由宿主在本步骤内继续实际制作，默认范围为 core 与 recommended，optional 保留候选。旧会话缺少该字段或显式为 false 时保持原来的计划与单图入口，不自动升级为批量任务。完整业务路径的额外逐件计划、分镜、文件索引等按宿主实际支持的附件保存；本地可使用真实可用的工具完成已授权制作并记录真实调用与文件。

制作范围沿用 MaterialPlan.deliveryScope 与用户请求：focused_deliverables 可基于既有核心设计只制作本轮海报等指定产物，不强加核心产品图；full_collaboration 仍按整套清单交付。适配依据继续复用现有设计内容。

## 步骤

1. 取得实际上下文，确认方向依据、设计校验和任务允许范围；mcp__collider__get_context 可用时才调用。用户已授权整套制作或代选时连续完成该范围，不要求每件物料重新点头；普通设想或未选方向不能假称已获确认。
2. 读取当前风格包和模板。它们只影响表现，不能推翻硬条件。
3. 整套制作先核对适配依据、核心产品解剖、功能边界、物料优先级、本轮范围和参考映射，补齐选定版本的真实身份素材。需要复用上游成图时提前声明其稳定任务 ID；这是待实现依赖，不声称图片已经生成或附入，不能因主图尚未生成而省略声明。只共享文字设计或同一张身份原图不构成额外成图依赖。涉及共享关键图的项等待该图实际视觉验收通过，无该依赖的就绪项可先行；按依赖将就绪独立物料放入滑动窗口，最多 4 个生成任务在途，就绪一件即可启动，不等凑满四件，任一完成即补入下一项。供应商或宿主限额更小则遵守，单次参考图数量上限另行检查。实际验图用独立的有界队列，本地默认 2 个验图槽，不占用 4 个生图槽；有尚未生成物料将其作为参考图的共用图优先进入验收，普通物料继续生图。优先级只决定排队，不改变实际附图、身份核验和输出哈希的通过要求。
4. 对每件产物写独立计划，将资产转译落实到具体部位、内容或体验状态，并说明材料感、配色、使用情境、构图、参考素材、文字区与禁止项。展示方式应体现该产物的功能和用户动作；同一物品仅换角色、配色、画幅或视角记为 variants。打样/生产阶段再补相应平面稿、尺寸和结构文件。
5. 既有主图路径提交 RenderPlan，再调用实际可用的 mcp__collider__image_generate 并引用真实 ID。独立物料走宿主真实支持的制作能力，尚不支持的项明确状态；不把为主图编写的契约当任意物料接口。
6. 既有海报路径用真实主图 assetId、当前 CopyPack 和模板调用 mcp__collider__poster_compose。只改文案或排版时复用有效主图；独立发布海报可有单独的叙事构图，由相应的物料计划与真实制作工具产出，不能谎称 poster_compose 支持该功能。
7. 视频准备按脚本制作镜头表、真实参考帧或关键帧、角色/道具/场景一致性表及逐镜提示词，区分尚未生成项。只有当前请求包括成片时才调用相应视频能力；没有成片请求也可以完整交付已约定的准备文件与素材。
8. 每项完成即保存实际附图列表、调用与输出证据，逐件读取结果做身份和设计验收，并回传宿主/画布的真实状态；不等整批完成才展示。整理统一入口、素材索引、原始/编辑/导出文件和真实哈希交给 quality-review。计划、生成成功和验收通过是不同状态；宿主无画布更新接口时用实际可用状态附件，不编造已更新回执。

## 主图规则

不增加未设计的配件、赠品、礼盒或文字。需要准确标识时实际附上来源可追溯的 Logo/符号素材，并验收具体形态；没有可用素材则补采或将依赖项待补素材，不用相似图形替代。用户已接受的原创抽象设计按其范围制作，不声称它是官方元素。

效果探索优先交付逐件外观效果图，包装平面稿、结构展开和刀版不作为本阶段必需项。用户要求打样/生产后再提供相应规格和文件；效果图不能称为已验证的生产文件。准确中文与品牌文字优先使用适当排版工具；产品上的可见文字应进入物料设计并接受实际图片检查。

模型不支持必要参考图或编辑时，切换实际可用且范围内的能力；仍无法实现则暂停准确身份依赖项，继续不依赖它的概念效果，不能以文字提到参考网站代替实际附图或声称保真已通过。

## 海报规则

既有 poster_compose 路径必须复用有效主图。文字测量、换行、溢出和概念标记由工具执行。该路径的海报失败只重试合成，不重新出图。整套发布中的新创意画面须作为独立物料，不能把全部海报强制做成同一主图的套版。

## 失败处理

单项工具失败仅影响该项及依赖它的任务，保留已完成项并继续独立就绪队列；请求状态或计费结果未知时先核查，不自动重复付费，该在途请求未明确终止前仍占用并发名额。修复依据当前宿主限额、用户授权范围和具体失败原因设定有界次数与停止条件，不因 Skill 自行提高花费，不执行无界循环。用户新指令优先于历史一轮修复惯例；限额用尽或阻断不可修复时逐件报告，不将整包误标为通过。不能编造素材 ID 或下载地址，不用示例图冒充新生成结果。
