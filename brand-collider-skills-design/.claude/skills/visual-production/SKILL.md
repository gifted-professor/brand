# 联名物料与视觉制作

## 输入与输出

可从 researchContext 参考构图、表现手法和素材线索。网页 URL 与案例 ID 不是可用素材 ID；未经当前素材登记与使用权确认，不把历史图片或标识当作参考资产提交。

输入为当前 DesignSpec、CopyPack、风格包、模板和已有素材。先阅读 [契约](references/CONTRACT.md)。整套请求必须阅读 [整套物料交付约定](references/CAMPAIGN_KIT.md)，按逐件清单制作，不能在交付两张总览卡片或几个尺寸变体后宣称整套完成。默认先做“效果探索”：饮品、杯托、折页、海报等各自有可评审的独立效果图，呈现具体外观、产品和故事设计；尺寸、刀版与结构展开在用户要求打样/生产后再补。

当前 RenderPlan、image_generate 与 poster_compose 契约仍只覆盖既有主图和复用主图海报路径。故事、物料清单、外观设计、逐件生成计划、分镜、文件索引等先保存为附件，不擅自添加 payload 字段或虚构批量物料/视频 MCP。网页的清单编排、逐件依赖与导出需要宿主另行实现；本地可使用当前实际可用的生成、编辑和文件工具完成授权任务，并记录真实调用与文件。

## 步骤

1. 取得实际上下文，确认方向依据、设计校验和任务允许范围；mcp__collider__get_context 可用时才调用。用户已授权整套制作或代选时连续完成该范围，不要求每件物料重新点头；普通设想或未选方向不能假称已获确认。
2. 读取当前风格包和模板。它们只影响表现，不能推翻硬条件。
3. 整套制作先核对物料家族、外观设计、文案、故事节点、参考来源及当前输出层级。确定统一美术设定，再生成共享角色/产品/场景参考，按依赖顺序制作逐件独立效果图。检查已有素材是否仍有效，避免无依据重生；不以缺少尺寸或结构展开阻断效果探索。
4. 对需生成的每件物料写独立计划，包含产品组件、材料感、配色、展示视角、构图、参考素材、文案覆盖区与禁止项。杯托实物效果图、饮品效果图、折页展示图和独立门店海报各自覆盖不同物料；只换画幅或标题不算新的设计家族。用户进入打样/生产阶段时，另加入尺寸适配、平面稿和结构展开等交付。
5. 既有主图路径提交 RenderPlan，再调用实际可用的 mcp__collider__image_generate 并引用真实 ID。独立物料走宿主真实支持的制作能力，尚不支持的项明确状态；不把为主图编写的契约当任意物料接口。
6. 既有海报路径用真实主图 assetId、当前 CopyPack 和模板调用 mcp__collider__poster_compose。只改文案或排版时复用有效主图；独立发布海报可有单独的叙事构图，由相应的物料计划与真实制作工具产出，不能谎称 poster_compose 支持该功能。
7. 视频准备按脚本制作镜头表、真实参考帧或关键帧、角色/道具/场景一致性表及逐镜提示词，区分尚未生成项。只有当前请求包括成片时才调用相应视频能力；没有成片请求也可以完整交付已约定的准备文件与素材。
8. 逐件读取实际结果做验收，整理统一入口、素材索引、原始/编辑/导出文件和真实哈希，将证据交给 quality-review。计划、生成成功和验收通过是不同状态。

## 主图规则

不增加未设计的配件、赠品、礼盒或文字。没有可用标识素材时不声称能保留官方 Logo。

效果探索优先交付逐件外观效果图，包装平面稿、结构展开和刀版不作为本阶段必需项。用户要求打样/生产后再提供相应规格和文件；效果图不能称为已验证的生产文件。准确中文与品牌文字优先使用适当排版工具；产品上的可见文字应进入物料设计并接受实际图片检查。

模型不支持参考图或编辑时明确告知并按宿主能力处理，不能假装已经保留像素级细节。

## 海报规则

既有 poster_compose 路径必须复用有效主图。文字测量、换行、溢出和概念标记由工具执行。该路径的海报失败只重试合成，不重新出图。整套发布中的新创意画面须作为独立物料，不能把全部海报强制做成同一主图的套版。

## 失败处理

工具失败保留已有产物；请求状态或计费结果未知时先核查，不自动重复付费。修复依据当前宿主限额、用户授权范围和具体失败原因设定有界次数与停止条件，不因 Skill 自行提高花费，不执行无界循环。用户新指令优先于历史一轮修复惯例；限额用尽或阻断不可修复时逐件报告，不将整包误标为通过。不能编造素材 ID 或下载地址，不用示例图冒充新生成结果。
